# GamepadAdaptor

`GamepadAdaptor` reflects an SDK `Gamepad` onto the bus. One line gives every button and axis a topic:

```java
GamepadAdaptor.attach(orchestrator, gamepad1, "g1");
```

After this, gamepad 1's state flows onto the bus at **60 Hz** — no polling code, no edge-detection code, nothing else.

## Topics published

Every **public non-static `boolean` field** becomes a button with three topics:

| Topic | Type | Meaning |
| --- | --- | --- |
| `g1/<button>` | `Boolean` | current state, published every poll |
| `g1/<button>/rising` | `Boolean` | fires (value `true`) on press (0→1) |
| `g1/<button>/falling` | `Boolean` | fires (value `true`) on release (1→0) |

Every **public non-static `float` field** becomes an axis topic:

| Topic | Type | Meaning |
| --- | --- | --- |
| `g1/<axis>` | `Float` | current value, published every poll |

The real SDK `Gamepad` (v11.2) yields **27 button fields** — including `a`, `b`, `x`, `y`, `circle`, `cross`, `square`, `triangle`, the four `dpad_*` keys, `left_bumper`, `right_bumper`, `start`, `back`, `guide`, `options`, `share`, `ps`, the stick buttons, `touchpad`, `touchpad_finger_1/2`, and `left_trigger_pressed` / `right_trigger_pressed` — and **10 axis fields**: `left_stick_x`, `left_stick_y`, `right_stick_x`, `right_stick_y`, `left_trigger`, `right_trigger`, and the four touchpad coordinates. Non-boolean/float fields (`id`, `timestamp`, `nextRumbleApproxFinishTime`) are skipped, and any field a future SDK adds is picked up automatically by the reflection.

## Reading the values

**Edges — subscribe** (fires once per press):

```java
@SubscribedTo(topic = "g1/right_bumper/rising")
@OnHardwareThread
public void grab(Boolean v) {
    claw.run(s -> s.setPosition(GRAB));
}
```

**Axes — poll** (inside a loop):

```java
double y = -orchestrator.getLatestValue("g1/left_stick_y", Float.class)
                         .map(Float::doubleValue).orElse(0.0);
```

> **Axes are `Float`.** The SDK stores them as `float`, so `getLatestValue(name, Double.class)` returns an empty `Optional` — always fetch with `Float.class` and map to `double` for math.

## Details worth knowing

- `attach` registers a node named `GamepadAdaptor:g1` and returns that name; it is cleaned up automatically when the orchestrator closes.
- All topics are pre-created at attach time, so subscriptions made right after `attach` (in the same `onSafeInit`) never miss values.
- The adaptor polls on the **scheduler pool** — gamepad reads never need the hardware thread.
- The base `<button>` topic publishes current state every tick, so it also works as a "held" input; `/rising` and `/falling` publish only on the transition.

## Two gamepads

```java
GamepadAdaptor.attach(orchestrator, gamepad1, "g1");
GamepadAdaptor.attach(orchestrator, gamepad2, "g2");
```

Each adaptor is independent; the parent prefix keeps their topics apart. See the [two-controller recipe](/docs/recipes/two-controller-teleop) for the robot-validated driver/operator split.

## SafeOpMode defaults

When you extend [`SafeOpMode`](/docs/ftc/safe-opmode), gamepad publishing defaults depend on the OpMode type:

| OpMode annotation | `publishGamepads` default | Behavior |
|---|---|---|
| `@TeleOp` | `true` | Gamepad adaptors attach automatically via `attachGamepad` |
| `@Autonomous` / none | `false` | Gamepads are **not** published — opt in by setting `publishGamepads = true` |

Use [`SafeOpMode#attachGamepad(Object, String)`](/docs/ftc/safe-opmode) instead of calling `GamepadAdaptor.attach` directly so the default is respected:

```java
@TeleOp(name = "Main TeleOp")
public class MainTeleOp extends SafeOpMode {
    @Override protected void onSafeInit() {
        // publishGamepads defaults to true for @TeleOp.
        attachGamepad(gamepad1, "g1");
        attachGamepad(gamepad2, "g2");
    }
}
```

```java
@Autonomous(name = "Red Alliance Auto")
public class RedAuto extends SafeOpMode {
    @Override protected void onSafeInit() {
        // publishGamepads defaults to false for Autonomous.
        attachGamepad(gamepad1, "g1");          // no-op: not published
        publishGamepads = true;                  // opt in
        attachGamepad(gamepad1, "g1");           // now attached
    }
}
```

To opt out of gamepad publishing in a `@TeleOp` OpMode, set `publishGamepads = false` in `onSafeInit()` before calling `attachGamepad`.
