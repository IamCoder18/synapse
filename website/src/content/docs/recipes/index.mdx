# Recipes

Only recipes that have been **verified on a real robot** live here. Each page links the pull request where the code was tested, with the on-robot verification notes.

- **[Mecanum drive](/docs/recipes/mecanum-drive)** — four-motor robot-centric drivetrain with per-wheel telemetry and a direction test. Verified on the 23684 Canopy-Biobuzz competition robot ([PR #3](https://github.com/ATAARobotics/23684-Canopy-Biobuzz/pull/3)).
- **[Two-controller teleop](/docs/recipes/two-controller-teleop)** — driver + operator gamepads with a shared-input intake. Verified in the same PR.

## Supported, recipe pending

Everything below is **fully supported by the library today** — the APIs are stable and documented. What these patterns don't have yet is a recipe page, and recipes only appear here once they've been verified on a real robot. Use the linked APIs to build them now:

- **Field-centric mecanum drive** — IMU lookup via [`safeMap.device(IMU.class, ...)`](/docs/ftc/safe-device), heading rotation before the mix.
- **Bulk sensor reads** — [`bulkRead`](/docs/ftc/hardware-actions) for motors, encoders, and current.
- **Hold hardware writes until the match timer starts** — [`restrict("write", GateMode.QUEUE)`](/docs/guides/gating-hardware) at init, `release("write")` from a `g1/x/rising` trigger, and a slotted (`@OnHardwareThread(labels = "write", slot = ...)`) teleop stream that collapses to the latest setpoint. Walkthrough: [gating hardware work](/docs/guides/gating-hardware).
- **Freeze a subsystem while an action runs** — [`restrict(...).queue().except(...)`](/docs/guides/gating-hardware) around an [`orchestrator.runAction(...)`](/docs/concepts/orchestrator), with `release` in `whenComplete` and slots bounding the held teleop stream. Walkthrough: [gating hardware work](/docs/guides/gating-hardware).
- **Autonomous skeleton** — state machine in a [`@RunPeriodically`](/docs/annotations/run-periodically) loop over topics.
